## Recovery demonstrated

The [build and publication run](https://github.com/mbodge/theartist/actions/runs/34796889611) failed only after live verification, when repeated historical file metadata exceeded the reflection context budget. The encrypted checkpoint retained the completed build and deployment. Context preparation now sends file paths and concise deployment records while retaining full metadata in canonical memory.

The [reflection recovery run](https://github.com/mbodge/theartist/actions/runs/34797553464) restored that checkpoint, reused the same build and app, and completed reflection. Its final catalog upload encountered the original 1.5 MB limit: the accumulated public record and source bundles were 1,588,221 bytes. The configured ceiling is now 2 MB. No build or model result was erased to recover either failure.

The [catalog recovery run](https://github.com/mbodge/theartist/actions/runs/34797915341) **succeeded**, published the complete catalog, and saved canonical memory. A fresh restore confirmed the completed cycle, reflection, published app, and valid event chain. The latest [Linux CI run](https://github.com/mbodge/theartist/actions/runs/34797884493) passed **97 tests with zero skips**. Daily model-budget exhaustion now produces a successful waiting state instead of another failed workflow notification. App inspection and withdrawal checks run before model dispatch, including while planning waits for its daily allowance.

## What this establishes

This is evidence of a hosted build → test → publish → live interaction check → reflect → checkpoint loop. It does not establish customer demand, independent product quality, willingness to pay, or a generally reliable autonomous business. The founder's reflection retains questions about maintenance capacity and user comprehension; the earlier managed backend's cleanup remains unresolved. Social outreach, email, purchasing, and factory fulfillment are not connected.

The original CSV experiment and the first hosted rerun remain non-passes. The original accidental app publication remains withdrawn. The new candidate uses a prospectively changed environment contract and a minimal product repair; it does not retroactively change earlier outcomes.

The scheduled runtime uses GitHub Actions, OpenAI Responses, Cloudflare Workers, and an authenticated encrypted checkpoint. It does not depend on a running laptop. Storage, stage calls, workshop jobs, elapsed time, and publication counts remain bounded. The static catalog and checkpoint branch are v1 storage choices; expanding the studio requires a storage migration rather than deleting memory or repeatedly raising limits.
